# Legion Control — расширенный аудит alpha.59

База аудита — `31f6c83b9cb75fd3ed7c82694df895c89e5935c8`. На этой ревизии прошли [Android CI](https://github.com/lolokeksu09/Legion-Control/actions/runs/45884878716) и [постоянная подпись](https://github.com/lolokeksu09/Legion-Control/actions/runs/45884878748). План развития центров и требования UA сохраняются в [Unified Architecture](UNIFIED-ARCHITECTURE-0.2.0.md). Здесь фиксируются новые наблюдения и работы текущего прохода.

## Контуры и зависимости

| Область | Владелец / ограничение |
| --- | --- |
| Измерения и JNI | Android поставляет исходные измерения, Rust валидирует и хранит кольцевое окно в 64 точки. Схема SQLite и JNI ABI не требуют смены для работ EA-01–EA-07. |
| SQLite / резервная копия | `LocalHistoryStore` и именованные схемы модулей. Сохранить существующие миграции, восстановление после прерванного импорта и границы чтения архива. |
| Запись и медиа | `GameSessionRecorderService` владеет записью телеметрии. `CaptureCoordinator` сериализует запись экрана, Replay и скриншоты. Android MediaProjection и SAF требуют отдельного согласия пользователя. |
| Устройство и периферия | `MainActivity` владеет страницей диагностики и встроенными Fragment. Полноэкранный дисплей и монитор ввода контроллера используют отдельные Activity. |
| Доступ и системные записи | `CapabilityAccessBackend`, `ShizukuAccessBackend`, `SystemControlPanel`, существующие apply/readback/restore. Проверить отказ, отключённый доступ и неподдерживаемый OEM. FPS сторонней игры, GPU и системная загрузка CPU остаются за пределами подтверждённых измерений. |
| Подпись | Постоянный сертификат и пакет сохраняются. PR проверяется до слияния. Подпись выпускается для точного SHA main после успешного Android CI. |

Порядок работ — закрытый вход и маршруты, общая аналитика и жизненный цикл, интерфейс состояния, затем CI и подписанный артефакт. Статический обзор не подтверждает работу Wi‑Fi/IPv6, запись со звуком, физические сенсоры, OEM-настройки, наложение, Shizuku, TalkBack или расход батареи на Legion Y70. Для этих сценариев остаётся отдельная приёмка устройства. Длинный эмуляторный прогон запускается только при необходимости согласно задаче.

## Реализация и проверка

- EA-01. Сохранён компонент `.NavigationHostActivity`. Он открывает приватный `.LegionHubActivity` чистым Intent. Из приложения и плитки запросы по-прежнему поступают в закрытый хост.
- EA-02/05. Из записи, Главной и поиска открывается один экран аналитики. Убраны четыре прежних экрана и их ViewModel. Отчёты по открытой записи читают доступные точки и события. ZIP одной записи и A/B-сравнение требуют завершения. Общий экран содержит выбор записи, CSV и системное меню отправки. Убрано быстрое сравнение двух последних записей из общего списка, которое могло сравнивать разные приложения.
- EA-03/07. Встроенные лаборатории переходят через выбор страницы текущего центра. История SQLite загружается при входе в историю. Последняя игровая серия читается один раз за запрос истории записи. Замеров RAM/CPU/батареи на Legion Y70 пока нет.
- EA-04. Исходные проверки сохраняют маршруты и действия, исключают фиксированные числа экранов и диалогов. Опциональный Android smoke использует идентификаторы реальных элементов, переходы ОС и успешное выполнение AndroidJUnitRunner с ненулевым числом тестов. Проверки старых подписей UI заменены тестами навигации, поиска команд и сохранения фактической метки записи. В приложении по-прежнему используется один общий AMOLED-стиль.
- EA-06. При исчезновении Binder запрос Shizuku завершается штатным отказом. Возобновление связи и чтение OEM-значений требуют физической проверки.
