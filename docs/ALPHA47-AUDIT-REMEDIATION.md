# Alpha 47 — исправления по аудиту Alpha 46

**Основание:** [AUD-01…AUD-11](FULL-AUDIT-ALPHA46.md) (документ находится в PR #52), [Issue #53](https://github.com/lolokeksu09/Legion-Control/issues/53). **Текущая версия в Gradle остаётся Alpha 46:** до проверки исправлений новый подписанный релиз не выпускается.

## Реализовано в ветке исправлений

- **AUD-01:** постоянные подписи для всех четырёх полей Smart Profiles. Вместо технического поля «420» интерфейс принимает `42,0` / `42.0` °C, сохраняет прежние 420 дециградусов в SQLite. Парсер отвергает некорректные/неоднозначные строки, тестирует roundtrip и диапазон 30–55 °C. Поля связаны с доступными label через `labelFor`.
- **AUD-02:** резервный ZIP остаётся формата v1, SQLite — v12. До записи SQLite создаётся атомарный локальный журнал с импортируемыми preferences + SHA256. В *одной* SQL-транзакции импортируются строки и меняется `PRAGMA application_id` на случайный идентификатор операции. Только после COMMIT в четыре preferences файла записываются новые настройки. При process-death приложение до открытия Activity/Service сверяет журнал с SQLite-маркером: если COMMIT был — повторно применяет настройки и очищает журнал; если COMMIT не был — удаляет неактуальное намерение, оставляет текущие prefs. Ошибка восстановления оставляет файл журнала и сообщает предупреждение в Game Hub. Содержимое журналируемых prefs не логируется и не экспортируется.
- **AUD-02 recovery UX:** Capture Studio предоставляет отдельное ручное действие «Завершить прерванное восстановление»; если автоматический повтор не сработал, пользователь может повторить его без реимпорта ZIP, без удаления существующей SQLite и без обхода активного MediaProjection.
- **AUD-03:** корректировка первичного аудита: инструментальный `FullBackupInstrumentedTest` **уже запускался** через `scripts/check_android_emulator_smoke.py:218–231`, а не только компилировался. Тест дополнен детерминированным исключением после SQLite COMMIT, с проверкой фактического дозавершения prefs из журнала и очистки журнала.
- **AUD-04:** новый `ConnectivityRunTicket` разделяет queued/running. Отмена до входа в callable сбрасывает `testing` немедленно и не позволяет старой задаче начать измерения после нового запроса. Действующее измерение завершает worker, не подменяя безопасную отмену таймаутом.
- **AUD-05:** смена сервера увеличивает generation и запрещает показывать старые результаты истории или диагностики под новым target.
- **AUD-06:** синхронный отказ `startActivity` после применения Game Launch Profile теперь сразу запрашивает compare-before-restore глобальных настроек и показывает результат возврата.
- **AUD-07:** убраны устаревшие `alpha.20/21/22/23` из сетевого, аудио, тактильного модулей и Application Center; emulator smoke обновлён.

## Неизменные контракты

Идентификатор `dev.lolokeksu.legioncontrol`, Android min/target, подпись, JNI ABIs, MediaProjection consent, SQLite user_version=12, существующие таблицы/колонки, структура ZIP, сохранённые пользовательские профили, отсутствие Root/Shizuku, отсутствие автоматического запуска системных настроек.

`application_id` — отдельное служебное поле заголовка SQLite; не является `user_version`, не меняет миграции и не подменяет версию базы.

## Обязательные проверки

- [ ] Kotlin JVM: `SmartProfileTemperatureTest`, `ConnectivityRunTicketTest` и прежние unit tests.
- [ ] Kotlin/Rust build + исходные Python contracts на exact PR SHA.
- [ ] Android 35 emulator: существующий `FullBackupInstrumentedTest` с новым fault injection, UI smoke, Smart Profiles label, Game Session, Tools, History и вкладки.
- [ ] Визуальный осмотр нового Smart Profiles из artifacts CI.
- [ ] Код-ревью порядка журнал→COMMIT→preferences→очистка, ошибочных и повторных запусков.
- [ ] Физический Lenovo Legion Y70: **NOT RUN** до отдельного доступа к устройству.

**Известное ограничение:** тест с исключением после SQLite COMMIT моделирует границу прерывания, но не равен физическому выключению питания/убийству Android процесса при последовательных writes. Для окончательной аппаратной приёмки нужен отдельный тест на устройстве/эмуляторе с process kill по каждому checkpoint.
