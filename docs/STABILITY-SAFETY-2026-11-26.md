# Stability & Safety — первый пакет

Основание: [аудит LC-01–13](AUDIT-2026-11-26.md).

## LC-01a — явная публикация

Подписанный workflow запускается вручную, publish по умолчанию false. Явная публикация требует publish=true, успешный Android CI точного main SHA и отсутствующий тег. Защита от замены APK и постоянный сертификат сохранены. Одновременные подписанные workflow сериализуются. Версия остаётся 49; новый tag/версия требуют отдельного решения. Ручной запуск с publish=false создаёт проверяемый подписанный артефакт, но не публикует его.

## LC-04a — подтверждение системных записей

SmartSystemControls сохраняет исходные значения через проверенный commit перед записью. Громкость, яркость, режим и тайм-аут проверяются readback. Восстановление яркости и тайм-аута независимо; журнал соответствующего параметра удаляется только после подтверждения. Ключи старого undo сохранены. Добавлены VerifiedSettingWrite, четыре JVM-теста и source gate.

## LC-02a — честное сообщение DND

API 35+ сообщает о запросе изменения правила Legion Control, а не о гарантированном глобальном DND. [Документация Android](https://developer.android.com/about/versions/15/behavior-changes-15#dnd). GameLaunchProfiles пока не переработан.

## LC-02b — DND-профили Android 15+

Для targetSdk 36 на Android 15+ `setInterruptionFilter()` управляет не глобальным фильтром, а неявным `AutomaticZenRule`, принадлежащим приложению. GameLaunchProfiles теперь на API 35+ читает только правило Legion Control через `getAutomaticZenRules()` и `getAutomaticZenRuleState()`, сохраняет состояние правила и его interruption filter, а при возврате сверяет оба значения. Для ранее существовавшего правила используется `AutomaticZenRule.Builder` и `updateAutomaticZenRule`, чтобы восстановить filter и enabled state без переключения агрегированного DND. Правила других приложений и глобальный агрегированный DND не используются как undo-значение. Формат undo обновлён до v2; v1 продолжает декодироваться. Старый v1 DND-ticket на API 35+ намеренно пропускается и сообщает предупреждение, потому что он содержит только глобальный фильтр и не позволяет безопасно восстановить прежнее состояние app-rule.

Добавлены тесты совместимости v1/v2 и source guard. Реальное поведение ещё нужно проверить на Android 15/16 и OEM-прошивках.

## LC-06a — границы ZIP recovery

Усилен emulator fault-injection: отдельный crash после durable journal, но до SQLite commit должен удалить несогласованный intent и не применять preferences; существующий сценарий crash после DB commit проверяет повторяемый replay. Это фиксирует протокол как recoverable saga (SQLite marker + durable intent + idempotent preference replay), а не как одну атомарную транзакцию между SQLite и SharedPreferences.

## LC-04b — защита пользовательских изменений при возврате

Каждая новая ручная операция яркости/тайм-аута сохраняет исходное и последнее запрошенное значения до обращения к Android. При возврате параметр меняется обратно только если текущее значение совпадает с последним запросом Legion Control; уже исходное значение просто закрывает запись, а третье значение считается внешним изменением и не перезаписывается. Яркость, режим автояркости и тайм-аут восстанавливаются независимо. Старые undo-записи без expected value сохраняют legacy-поведение: одноразовый возврат исходного значения, поскольку определить внешнее изменение задним числом невозможно.

Добавлены четыре JVM-теста политики сравнения. Readback остаётся наблюдением, не атомарной транзакцией; нужна проверка на прошивках Motorola/Samsung.

## LC-03a — восстановление при запуске

`LegionApplication.onCreate()` больше не открывает SQLite и не воспроизводит ZIP-журнал на UI-потоке. При отсутствии pending journal запуск не планируется. При наличии журнал обрабатывается отдельным background executor с пониженным приоритетом. `NavigationHostActivity` ждёт результат; ошибка явно показана, журнал сохраняется, пользователь может продолжить с предупреждением и воспользоваться существующим ручным повтором в Capture Studio. Успешный повтор снимает startup warning для последующего пересоздания Activity. Quick Tile направлен через тот же launcher gate. Все пять сервисов, которые могут начинать запись, захват или менять игровые настройки, отклоняют новые start/refresh-команды до фактического успешного recovery; простое продолжение с предупреждением не разблокирует захват. Команды остановки остаются доступными. Добавлены четыре JVM-теста координатора и source gate.

Граница: физическое измерение cold-start/ANR и проверка восстановления на Motorola/OEM пока не выполнены. Новые прямые entry points должны соблюдать тот же gate.

## LC-05a — адаптивная память Instant Replay

Видео-лимит теперь рассчитывается от `Runtime.maxMemory()` (до 1/8 heap, hard cap 80 МиБ; для low-RAM устройства — половина). AAC получает отдельный меньший бюджет (до 1/128 heap, hard cap 8 МиБ). `onTrimMemory` выставляет неблокирующий флаг; codec thread сокращает лимиты, video eviction сохраняет границы GOP, audio сбрасывает старые пакеты. Статус Replay показывает выбранные бюджеты.

Frozen export по-прежнему удерживает ссылки на старые encoded samples, пока live buffer наполняется новыми: пиковое перекрытие двух video windows остаётся возможным, но каждый window теперь ограничен heap-relative budget. Это не измерение PSS и не гарантия отсутствия OOM. Нужны реальные замеры на Legion Y70 и слабом Android-устройстве.

## LC-04c — общий арбитр системных настроек

Ручные операции Smart Profiles и Game Toolbox, включая шаги громкости, используют существующий неблокирующий ProfileMaintenanceGate. При наличии game undo ручные записи и screen restore отклоняются до возврата игрового профиля. Новый профиль с яркостью не перезаписывает ручной brightness undo. Новые ручные изменения блокируются при pending ZIP; ручной возврат допустим при отсутствии game undo и активного maintenance lock. Громкость, режим и яркость игрового профиля подтверждаются readback; ошибки используют существующий rollback. Ограничение консервативное: ручные действия заблокированы при активном game ticket даже для независимых полей. Внешние процессы Android не сериализуются gate.

Instrumentation test проверяет, что при активном game ticket ручной callback не выполняется, ticket сохраняется. Source guard проверяет пять ручных методов и шаги громкости overlay. Новые тесты требуют CI точной ревизии.

## LC-08a — Capability Engine

CapabilityAccessPolicy различает READY, DISABLED, PERMISSION_REQUIRED, UNSUPPORTED и UNKNOWN. CapabilityAccessBackend независимо читает public API для уведомлений, overlay, Usage Access, DND, WRITE_SETTINGS и громкости. Неподдерживаемые функции (FPS чужой игры, OEM Boost) не предлагают выдачу бессмысленных разрешений. DND показывает право управления, а не текущую активацию; уведомления — app-wide, не отдельные каналы. SmartCompatibilityBackend, SmartSystemControls.status и Game Toolbox используют общие состояния. В Smart Profiles добавлены явные переходы к настройкам уведомлений, Usage Access и overlay. Нет новых разрешений, фонового polling, автоматической выдачи доступа или изменения существующих runtime guards.

Пять JVM-тестов политики и source guard. Capability snapshot не заменяет проверку разрешения непосредственно перед системной записью. Интеграция остальных экранов и индивидуальных каналов уведомлений остаётся открытой.

В run 45825495567 сборка прошла, но post-commit ZIP instrumentation получил отказ на непустой базе: строка удаления тестовой БД была случайно закомментирована после комментария. ## LC-08b — расширение Capability Engine

CapabilityAccessBackend предоставляет отдельные probes для Usage Access, overlay, уведомлений приложения/канала, DND, WRITE_SETTINGS, управления громкостью и RECORD_AUDIO. Авто-профиль проверяет соответствующие настройки до запуска, а watchdog проверяет только необходимые доступы, включая действующий канал Game Toolbox. Неполученное состояние блокирует watchdog; до запуска отсутствие ещё не созданного канала допускается, известный выключенный канал блокирует запуск. Ссылки на системные настройки уведомлений и канала открываются только по нажатию. Capture Studio показывает разрешение игрового аудио отдельно от реальной возможности записи конкретной игры; MediaProjection consent и прямые RECORD_AUDIO gates не изменены. Диагностика Usage Access использует общий probe.

## LC-05b — оптимизация Replay hot path

Счётчик sync frames обновляется при добавлении, удалении и очистке; проверка наличия следующего GOP больше не сканирует очередь. SAVE формирует максимум один список ссылок только после нахождения пригодного keyframe; старые или короткие окна не выделяют список. При отсутствии пригодного окна повторная попытка SAVE выполняется не чаще одного раза за 100 мс, вместо каждого codec poll. Лимиты памяти, immutable sample contract, 1-секундный минимум, аудиосинхронизация, safety stop и продолжение записи при экспорте сохранены. Перекрытие frozen/live буферов остаётся ограниченным существующими бюджетами, не измерено на устройстве.

Три новых теста composite access, четыре теста Replay (повторные eviction/clear, clipped snapshot stability, короткое окно), обновлены source guards. CI exact revision и физическая проверка требуются. Никаких новых разрешений, миграций, изменения подписи или версии.

## LC-05c — фактическое состояние Replay

Статус по запросу показывает реально удерживаемую длительность по PTS, количество encoded samples и байты сжатого видеобуфера относительно лимита. Снимок согласован под одним lock, обновляется codec thread раз в секунду только во время захвата, хранится в RAM и очищается при остановке. Нет нового polling UI, записи в SharedPreferences каждую секунду, оценки PSS, измерения FPS игры или обещания точной экспортируемой длительности. Добавлен тест stats до/после trim и clear.

Вкладка «Настройки» Game Hub теперь использует CapabilityAccessBackend вместо отдельных проверок. Android-free PermissionCenterModel описывает шесть управляемых доступов и три технические возможности/ограничения. Неподдерживаемые возможности не имеют бессмысленного перехода к разрешениям; неизвестный результат не считается готовым. Некликабельные ограничения не имитируют кнопки. Добавлены четыре JVM-теста модели и source guard. Главная показывает до трёх уже сохранённых избранных игр с переходом в существующую карточку, затем библиотеку и быстрые действия. - Проверка конфигурации: scripts/check_release_signing.py, scripts/run_source_checks.py.
- Для изменённой ревизии требуется CI; старый зелёный CI не доказывает новую ревизию.
- Нет изменения разрешений, SQLite, applicationId, ABI, версии или подписи. Релиз не запрашивался.

Readback — наблюдение, не атомарная транзакция. Нужны физические проверки отказа доступа, частичной записи и внешних правил DND.

Бюджет относится к уникальным удерживаемым H.264 sample bytes, не к PSS: временная аллокация codec output, индексы/объекты, MediaCodec, AAC и muxer считаются отдельно. Цена строгого бюджета — временное укорочение/пауза live GOP при большом экспорте; активный экспорт не отменяется.
