# Legion Control

Новый самостоятельный проект для Lenovo Legion Y70. Первая стадия — **реальный backend**, интерфейс развиваем позже.

## Стек
- **Kotlin/Android:** получение данных через публичные Android API, разрешения и жизненный цикл.
- **Rust:** проверка показаний и расчёт изменений батареи в ограниченном 64-сэмпловом буфере.
- **JNI:** связь между Kotlin и Rust для Android ARM64.

Текущий backend не отправляет данные на сервер, не меняет параметры телефона и не требует Shizuku или Root. Это отдельный проект: исходный `Lenovo-Y70` оставлен без изменений.

См. `rust-core/`, `android-core/`, `docs/BACKEND.md`. Следующие шаги: Rust unit tests в CI, Android JNI сборка, затем легковесный Kotlin-интерфейс. Никаких заявлений об улучшении FPS, сенсорного отклика или Bypass.

Версия backend: `0.1.0-alpha.9`.

## v0.1.0-alpha.2 — реальные Rust-статистики и релизная подпись

- Backend Rust по запросу возвращает **минимальную, максимальную и среднюю температуру батареи** по последним 64 реальным сэмплам. Данные читаются новым JNI-методом, а не рассчитываются в Kotlin.
- Проверяются пустая история, сохранение только последних 64 образцов, отрицательные температуры и отсутствие побочных изменений при чтении статистики.
- Настроен **постоянный PKCS12-релизный ключ**: сборка APK c ним выполняется вручную в GitHub Actions, если владелец установил секреты. Публичный отпечаток фиксирован; приватный ключ в репозитории отсутствует.
- **Инструкция подписи:** [docs/RELEASE-SIGNING.md](docs/RELEASE-SIGNING.md). До установки четырёх секретов workflow release не может выпускать подписанные APK. Debug CI доступен независимо.
- Важное ограничение: старый debug APK имеет другой сертификат. При переходе на release может потребоваться удалить прежнюю версию; будущие release-версии обновляются друг поверх друга только с тем же ключом.

Пока нет фонового мониторинга, серверной отправки, Root/Shizuku и изменения системных настроек.

## v0.1.0-alpha.3 — сеансы Rust и реальные данные питания

- **Нативный сеанс:** Rust хранит до 64 замеров в оперативной памяти, вычисляет длительность между первым и последним удержанным замером (через Android `elapsedRealtime`) и по подтверждению пользователя очищает историю. Сброс не меняет параметры телефона. После него нужен новый запрос измерения.
- **Android Power API:** статус и источник зарядки, напряжение батареи, ток `BATTERY_PROPERTY_CURRENT_NOW` (если доступен) и энергосбережение. Ток показывается как сырая величина со знаком, без ложного утверждения об эффективности, Bypass или состоянии здоровья батареи.
- **Экспорт:** кнопка «Поделиться отчётом» отправляет пользователем выбранному приложению последний успешный снимок через системный Android Sharesheet. Нет автоматической отправки и разрешения на доступ к памяти.
- **Подпись:** `versionCode=3`. Постоянный сертификат SHA-256 и четыре GitHub Secrets не менялись; `assembleRelease` по-прежнему запрещён без релизного ключа. Документ: [RELEASE-SIGNING](docs/RELEASE-SIGNING.md).

Тестирование: Rust unit tests, статическая проверка Kotlin JNI, Android CI debug-build. Проверка поведения на физическом Y70 выполняется отдельно после установки.

## v0.1.0-alpha.4 — сохраняемая диагностика

- **Локальная SQLite история:** отдельные сеансы и все успешно записанные измерения сохраняются в приватной базе, остаются после перезапуска приложения. Никаких сетевых запросов, разрешений на хранилище или автоудаления истории.
- **Rust:** сохраняет действующее окно из не более 64 измерений исключительно в RAM и вычисляет статистику/длительность; при перезапуске процесса начинается новый native-сеанс. SQLite и Rust выполняют разные задачи.
- **Экспорт CSV:** выбор имени и места хранения через штатный Android Documents UI (`ACTION_CREATE_DOCUMENT`), потоковая UTF-8 выгрузка без записи публичного файла до согласия пользователя. Содержит время, процент и температуру батареи, ток/напряжение, режим дисплея и признаки зарядки.
- **Проверка датчиков:** обнаружение акселерометра, гироскопа, освещённости, приближения, окружающей температуры через публичный `SensorManager`. Отсутствие видимого датчика не означает аппаратный дефект; данные CPU/GPU не выдаются за публичные датчики.
- **Исправление русского языка:** `2 измерения`, `5 измерений`, `21 измерение`. JVM регрессии проверяют формат CSV и склонение.
- **Релиз:** `versionCode=4`, прежний PKCS12 SHA-256 остаётся закреплённым. Подписанный APK автоматически собирается только при trusted push на `main` (после merge) либо вручную. Debug APK **нельзя** ставить поверх релизного без удаления приложения и потери локальных данных.

[Контракт хранения, экспорта и проверки на Lenovo Y70](docs/HISTORY.md). После получения APK проверь реальное сохранение между запусками, экспорт и датчики на устройстве.


## v0.1.0-alpha.5 — подключение backend к приложению

Новые public-API модули PR #6/#7 подключены к существующему действию «Обновить измерение». Результат диагностики RAM, доступного приложению раздела памяти, батареи, thermal headroom и режимов дисплея формируется вне UI-потока и добавляется в текущий отчёт/системный Sharesheet. Никаких новых экранов или дизайна: backend-first сохраняется. Новые измерения не записываются в старую SQLite-схему, она остаётся совместимой. `versionCode=5`; подпись только прежним релизным ключом, debug APK не заменяет signed release. Подробнее: [контракт backend](docs/BACKEND.md).


## v0.1.0-alpha.6 — Thermal + Battery Trends (backend)

The existing **Обновить измерение** action now decodes public Android thermal status and compares two accepted manual snapshots for thermal headroom and battery charge changes. The report explicitly separates missing data and contradictory battery gauge directions. No nominal-capacity or battery-health estimates; no Shizuku/Root or UI redesign. The same report is available through the existing share action. See [backend details](docs/BACKEND.md). The Android version is `versionCode=6`; the pinned release signer remains unchanged.

## v0.1.0-alpha.7 — диагностическая SQLite-история без потери данных

- **Обновление SQLite с v1 до v2:** добавляется таблица `diagnostic_samples`, старые сеансы и замеры сохраняются без изменений; нет очистки, удаления или автоподрезки.
- **Реальные показатели:** thermal status/headroom, заряд батареи и ток, доступная RAM и температура батареи (при наличии) сохраняются после каждого успешного ручного измерения.
- **Расчёт за несколько замеров:** по последним пяти снимкам того же сеанса вычисляются изменение температуры, диапазон температур, изменение заряда и средний темп изменения счётчика заряда. Это не мощность зарядного устройства и не диагностика износа.
- **Sustained Performance:** поддержка видна через Android API; текущее состояние чужих игр невозможно достоверно прочитать тем же публичным API, поэтому оно отмечено как неизвестное. Legion Control ничего не активирует.
- **Без изменений интерфейса и дизайна:** используется прежняя кнопка и текстовый отчёт, новый backend работает вне UI-потока.
- Сохраняется постоянная подпись; `versionCode=7`. Проверка потерь данных: реальный SQLite-тест `scripts/check_diagnostic_sqlite_migration.py`.

## v0.1.0-alpha.8 — расширенный CSV-экспорт

Через прежнюю кнопку **«Сохранить историю в CSV»** теперь экспортируются все старые измерения и семь дополнительных полей диагностики: `thermal_status`, `thermal_headroom`, `charge_counter_micro_ah`, `current_now_micro_a`, `current_average_micro_a`, `ram_available_bytes`, `diagnostic_timestamp_utc`. Первые 13 столбцов сохранены в прежнем порядке; старые записи без диагностики получают пустые поля, не нули. Экспорт потоковый, через системный выбор файла и без разрешений на хранилище. SQLite остаётся v2, история не удаляется. Версия APK `0.1.0-alpha.8`, `versionCode=8` с прежней релизной подписью. Новый функционал прежде изменений дизайна; без Shizuku и Root.

## v0.1.0-alpha.9 — данные о состоянии аккумулятора без Root

При существующем нажатии **«Обновить измерение»** Legion Control теперь читает дополнительные поля `ACTION_BATTERY_CHANGED`: Android Battery Health, число циклов (Android API 34+), сырой код дополнительного статуса зарядки, технологию батареи, её наличие и системный признак низкого заряда. Показывает оценку мощности **на клеммах батареи** из уже доступных напряжения/тока; это не измерение мощности зарядного блока и не признак Bypass. Android Health=`GOOD` — не измеренный процент износа. Поля, скрытые или неподдерживаемые прошивкой, показываются как «нет данных». Новый раздел подключён к прежнему ручному отчёту и системной отправке; нет новой кнопки, дизайна, Shizuku, Root или фонового опроса. SQLite v2 и 20-колоночный CSV без изменений. Подписанная версия `0.1.0-alpha.9` (`versionCode=9`).


## v0.1.0-alpha.10 — реальные датчики без Root/Shizuku

Кнопка «Снять показания датчиков» по запросу получает по одному свежему событию акселерометра, гироскопа, освещённости и приближения. Отчёт показывает значения, единицы, код точности Android и разницу с предыдущим сохранённым замером того же датчика. Отсутствующий датчик, отказ регистрации и тайм-аут за 3 секунды показываются отдельно, без поддельных нулей. Все слушатели снимаются после захвата или при уходе из Activity.

В SQLite v3 сохраняются только реальные корректные события, отдельно от Rust-сеансов и основной SQLite-диагностики. Миграции v1→v3 и v2→v3 добавляют таблицу без потери старых записей; «Последние показания датчиков» показывает историю после перезапуска. Дисковые операции выполняются вне UI-потока. Батарейный CSV остаётся 20-колоночным. CI проверяет JVM-валидацию и реальные SQLite-миграции; проверка работы датчиков на Lenovo Y70 проводится отдельно.


## v0.1.0-alpha.11 — диагностика датчиков и тепловая история

Backend-first обновление: реальный SensorManager сообщает режим работы каждого датчика, количество событий, число отброшенных событий, причину отклонения и задержку получения нового показания. Для датчика освещённости предусмотрено дополнительное ограниченное ожидание (6 секунд вместо 3); наличие показаний по-прежнему зависит от OEM/прошивки. Тайм-аут не подменяется нулём или старым значением. Слушатели удаляются после завершения и при уходе с экрана.

Все **завершённые** попытки, включая отсутствующие датчики, тайм-ауты и невалидные значения, сохраняются вместе с успешными событиями в одной транзакции SQLite v4. Миграция v1/v2/v3→v4 добавляет отдельную таблицу, не удаляя старую батарейную/сенсорную историю. Кнопка «Последние показания датчиков» теперь показывает последние статусы попыток, а не только успешные значения.

Добавлена «Тепловая история»: чтение уже сохранённых ручных замеров температуры батареи, Thermal Status и Thermal Headroom из SQLite v1/v2. Выводятся фактический диапазон температур, изменение для сопоставимых измерений и количество зафиксированных SEVERE-состояний. При текущем Thermal Status ≥3 появляется предупреждение в ручном отчёте. Это не температура CPU/GPU, не управление охлаждением и не фоновый мониторинг. Существующие 20 колонок CSV, Rust JNI и релизная подпись не меняются.

Проверки: JVM-тесты причин отклонения/тайм-аутов/теплового отчёта, реальная SQLite миграция (scripts/check_alpha11_diagnostics.py), существующие Kotlin/Rust CI и release gates. Физический запуск на Lenovo Y70 должен отдельно подтвердить обновление alpha.10→alpha.11, сохранность истории, доступность датчика света и отсутствие слушателей после закрытия.


## v0.1.0-alpha.12 — аналитика и полный диагностический архив

Backend-first версия добавляет три действия: «Профиль последнего сеанса», «Аналитика датчиков» и «Экспорт полной диагностики ZIP». Профиль использует только сохранённые ручные измерения температуры и уровня батареи, продолжительности, зарегистрированных режимов дисплея и энергосбережения. Аналитика датчиков подсчитывает реальные завершённые попытки, успехи, ошибки, отброшенные события и среднюю задержку успешных вызовов. Ни одна из этих метрик не означает измерение FPS, частоты сенсора, непрерывного расхода или состояния CPU/GPU.

При экспорте через системный выбор файла Android создаётся ZIP: battery.csv (старый 20-колоночный формат без изменений), sensor-attempts.csv, sensor-values.csv, thermal-history.csv и README.txt с числом строк. Экспорт только вручную, без сети и дополнительных разрешений. Из SQLite данные читаются потоком, неизвестные значения остаются пустыми, названия OEM-датчиков экранируются для CSV.

Основные чтения, экспорт и запись батареи перенесены с UI-потока в единый executor. Батарейная запись сохраняется раньше связанной диагностической записи с foreign key; завершение Rust-сеанса также ставится в очередь. База остаётся SQLite v4: новая миграция не требуется, предыдущая история не удаляется. Rust JNI, выпускной сертификат и права Android не менялись.

Тесты: Kotlin/JVM аналитика/ZIP, реальные запросы SQLite в scripts/check_alpha12_integration.py, сохранённые CI Rust/Android и release signing. На Lenovo Y70 необходима отдельная проверка запуска и экспорта.
