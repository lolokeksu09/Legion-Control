# Legion Control

Новый самостоятельный проект для Lenovo Legion Y70. Первая стадия — **реальный backend**, интерфейс развиваем позже.

## Стек
- **Kotlin/Android:** получение данных через публичные Android API, разрешения и жизненный цикл.
- **Rust:** проверка показаний и расчёт изменений батареи в ограниченном 64-сэмпловом буфере.
- **JNI:** связь между Kotlin и Rust для Android ARM64.

Текущий backend не отправляет данные на сервер, не меняет параметры телефона и не требует Shizuku или Root. Это отдельный проект: исходный `Lenovo-Y70` оставлен без изменений.

См. `rust-core/`, `android-core/`, `docs/BACKEND.md`. Следующие шаги: Rust unit tests в CI, Android JNI сборка, затем легковесный Kotlin-интерфейс. Никаких заявлений об улучшении FPS, сенсорного отклика или Bypass.

Версия backend: `0.1.0-alpha.17`.

## v0.1.0-alpha.2 — реальные Rust-статистики и релизная подпись

- Backend Rust по запросу возвращает **минимальную, максимальную и среднюю температуру батареи** по последним 64 реальным сэмплам. Данные читаются новым JNI-методом, а не рассчитываются в Kotlin.
- Проверяются пустая история, сохранение только последних 64 образцов, отрицательные температуры и отсутствие побочных изменений при чтении статистики.
- Настроен **постоянный PKCS12-релизный ключ**: сборка APK c ним выполняется вручную в GitHub Actions, если владелец установил секреты. Публичный отпечаток фиксирован; приватный ключ в репозитории отсутствует.
- **Инструкция подписи:** [docs/RELEASE-SIGNING.md](docs/RELEASE-SIGNING.md). До установки четырёх секретов workflow release не может выпускать подписанные APK. Debug CI доступен независимо.
- Важное ограничение: старый debug APK имеет другой сертификат. При переходе на release может потребоваться удалить прежнюю версию; будущие release-версии обновляются друг поверх друга только с тем же ключом.

Пока нет фонового мониторинга, серверной отправки, Root/Shizuku и изменения системных настроек.

## v0.1.0-alpha.3 — сеансы Rust и реальные данные питания

- **Нативный сеанс:** Rust хранит до 64 замеров в оперативной памяти, вычисляет длительность между первым и последним удержанным замером (через Android `elapsedRealtime`) и по подтверждению пользователя очищает историю. Сброс не меняет параметры телефона. После него нужен новый запрос измерения.
- **Android Power API:** статус и источник зарядки, напряжение батареи, ток `BATTERY_PROPERTY_CURRENT_NOW` (если доступен) и энергосбережение. Ток показывается как сырая величина со знаком, без ложного утверждения об эффективности, Bypass или состоянии здоровья батареи.
- **Экспорт:** кнопка «Поделиться отчётом» отправляет пользователем выбранному приложению последний успешный снимок через системный Android Sharesheet. Нет автоматической отправки и разрешения на доступ к памяти.
- **Подпись:** `versionCode=3`. Постоянный сертификат SHA-256 и четыре GitHub Secrets не менялись; `assembleRelease` по-прежнему запрещён без релизного ключа. Документ: [RELEASE-SIGNING](docs/RELEASE-SIGNING.md).

Тестирование: Rust unit tests, статическая проверка Kotlin JNI, Android CI debug-build. Проверка поведения на физическом Y70 выполняется отдельно после установки.

## v0.1.0-alpha.4 — сохраняемая диагностика

- **Локальная SQLite история:** отдельные сеансы и все успешно записанные измерения сохраняются в приватной базе, остаются после перезапуска приложения. Никаких сетевых запросов, разрешений на хранилище или автоудаления истории.
- **Rust:** сохраняет действующее окно из не более 64 измерений исключительно в RAM и вычисляет статистику/длительность; при перезапуске процесса начинается новый native-сеанс. SQLite и Rust выполняют разные задачи.
- **Экспорт CSV:** выбор имени и места хранения через штатный Android Documents UI (`ACTION_CREATE_DOCUMENT`), потоковая UTF-8 выгрузка без записи публичного файла до согласия пользователя. Содержит время, процент и температуру батареи, ток/напряжение, режим дисплея и признаки зарядки.
- **Проверка датчиков:** обнаружение акселерометра, гироскопа, освещённости, приближения, окружающей температуры через публичный `SensorManager`. Отсутствие видимого датчика не означает аппаратный дефект; данные CPU/GPU не выдаются за публичные датчики.
- **Исправление русского языка:** `2 измерения`, `5 измерений`, `21 измерение`. JVM регрессии проверяют формат CSV и склонение.
- **Релиз:** `versionCode=4`, прежний PKCS12 SHA-256 остаётся закреплённым. Подписанный APK автоматически собирается только при trusted push на `main` (после merge) либо вручную. Debug APK **нельзя** ставить поверх релизного без удаления приложения и потери локальных данных.

[Контракт хранения, экспорта и проверки на Lenovo Y70](docs/HISTORY.md). После получения APK проверь реальное сохранение между запусками, экспорт и датчики на устройстве.

## v0.1.0-alpha.9 — данные о состоянии аккумулятора без Root

При существующем нажатии **«Обновить измерение»** Legion Control теперь читает дополнительные поля `ACTION_BATTERY_CHANGED`: Android Battery Health, число циклов (Android API 34+), сырой код дополнительного статуса зарядки, технологию батареи, её наличие и системный признак низкого заряда. Новый раздел подключён к прежнему ручному отчёту и системной отправке; нет новой кнопки, дизайна, Shizuku, Root или фонового опроса. SQLite v2 и 20-колоночный CSV без изменений. ## v0.1.0-alpha.11 — диагностика датчиков и тепловая история

Backend-first обновление: реальный SensorManager сообщает режим работы каждого датчика, количество событий, число отброшенных событий, причину отклонения и задержку получения нового показания. Для датчика освещённости предусмотрено дополнительное ограниченное ожидание (6 секунд вместо 3); наличие показаний по-прежнему зависит от OEM/прошивки. Тайм-аут не подменяется нулём или старым значением. Слушатели удаляются после завершения и при уходе с экрана.

Все **завершённые** попытки, включая отсутствующие датчики, тайм-ауты и невалидные значения, сохраняются вместе с успешными событиями в одной транзакции SQLite v4. Миграция v1/v2/v3→v4 добавляет отдельную таблицу, не удаляя старую батарейную/сенсорную историю. Кнопка «Последние показания датчиков» теперь показывает последние статусы попыток, а не только успешные значения.

Добавлена «Тепловая история»: чтение уже сохранённых ручных замеров температуры батареи, Thermal Status и Thermal Headroom из SQLite v1/v2. Выводятся фактический диапазон температур, изменение для сопоставимых измерений и количество зафиксированных SEVERE-состояний. При текущем Thermal Status ≥3 появляется предупреждение в ручном отчёте. Это не температура CPU/GPU, не управление охлаждением и не фоновый мониторинг. Существующие 20 колонок CSV, Rust JNI и релизная подпись не меняются.

Проверки: JVM-тесты причин отклонения/тайм-аутов/теплового отчёта, реальная SQLite миграция (scripts/check_alpha11_diagnostics.py), существующие Kotlin/Rust CI и release gates. Физический запуск на Lenovo Y70 должен отдельно подтвердить обновление alpha.10→alpha.11, сохранность истории, доступность датчика света и отсутствие слушателей после закрытия.


## v0.1.0-alpha.12 — аналитика и полный диагностический архив

Backend-first версия добавляет три действия: «Профиль последнего сеанса», «Аналитика датчиков» и «Экспорт полной диагностики ZIP». Профиль использует только сохранённые ручные измерения температуры и уровня батареи, продолжительности, зарегистрированных режимов дисплея и энергосбережения. Аналитика датчиков подсчитывает реальные завершённые попытки, успехи, ошибки, отброшенные события и среднюю задержку успешных вызовов. Ни одна из этих метрик не означает измерение FPS, частоты сенсора, непрерывного расхода или состояния CPU/GPU.

При экспорте через системный выбор файла Android создаётся ZIP: battery.csv (старый 20-колоночный формат без изменений), sensor-attempts.csv, sensor-values.csv, thermal-history.csv и README.txt с числом строк. Экспорт только вручную, без сети и дополнительных разрешений. Из SQLite данные читаются потоком, неизвестные значения остаются пустыми, названия OEM-датчиков экранируются для CSV.

Основные чтения, экспорт и запись батареи перенесены с UI-потока в единый executor. Батарейная запись сохраняется раньше связанной диагностической записи с foreign key; завершение Rust-сеанса также ставится в очередь. База остаётся SQLite v4: новая миграция не требуется, предыдущая история не удаляется. Rust JNI, выпускной сертификат и права Android не менялись.

Тесты: Kotlin/JVM аналитика/ZIP, реальные запросы SQLite в scripts/check_alpha12_integration.py, сохранённые CI Rust/Android и release signing. На Lenovo Y70 необходима отдельная проверка запуска и экспорта.


## v0.1.0-alpha.13 — 60-секундный тест батареи по запросу

Новый модуль **«Тест батареи · 60 секунд»** выполняет ограниченную 60-секундную серию реальных замеров батареи через публичные Android API и действующий Rust JNI с шагом около 10 секунд (0, 10, 20 … 60 с). Он работает **только при открытом Activity**; при сворачивании приложение снимает таймер, прекращает измерения и сохраняет итог со статусом APP_BACKGROUND. Тест можно остановить вручную, а при Android Thermal Status SEVERE (3+) или температуре батареи ≥45 °C он завершится досрочно. После трёх подряд неудачных измерений тест завершается с явной ошибкой. Это не управление охлаждением, энергосбережением или Bypass, и не гарантирует защиту устройства от перегрева. Не оставляйте нагревающийся аппарат под нагрузкой ради теста.

Отчёт показывает фактически принятые Rust/Android точки, изменение уровня и температуры батареи при достаточных данных, диапазон температуры и показания тока Android. Не выводятся FPS, температура CPU/GPU, износ, скорость разряда, ёмкость или эффективность зарядного блока. Тест хранится в отдельной новой таблице SQLite v5; старые записи аккумулятора, датчиков, thermal и сеансов остаются в прежних таблицах. Итоги доступны через кнопку **«История тестов батареи»** после перезапуска, включая причину раннего завершения и число реально записанных в SQLite замеров. В полный диагностический ZIP добавлен timed-tests.csv, а прежний battery.csv не меняется.

Проверки: JVM-тесты таймера и ранней остановки, реальная SQLite миграция v1/v2/v3/v4→v5 без удаления данных и тест включения нового CSV в ZIP. Нужна отдельная проверка реальных интервалов и жизненного цикла на Lenovo Y70; CI подтверждает код и APK, но не измерение на телефоне. Устанавливайте подписанный APK поверх предыдущего, не удаляя приложение.


## v0.1.0-alpha.14 — Gaming Lab: 10 ручных диагностик

Старый интерфейс и Rust JNI сохраняются. По новой кнопке Gaming Lab открываются десять возможностей:

1. Network Analyzer: DNS + пять TCP-подключений к one.one.one.one:443, статистика соединений, ошибки и разброс. Это НЕ ICMP ping и НЕ задержка Wild Rift.
2. Battery Intelligence: счётчики остаточного заряда и энергии Android BatteryManager, если доступны. Это НЕ измерение износа.
3. Thermal Guard: реальный Android thermal status/headroom и события пока открыт экран и пользователь включил подписку.
4. Touch Analyzer: собственный мультитач View, траектории нажатий, покрытие 3×3 и задержка доставки MotionEvent внутри Legion Control.
5. Frame Pacing: пять секунд Choreographer, интервалы и выбросы кадровых callback собственного приложения, НЕ FPS других игр.
6. Wi-Fi/LTE Inspector: активный транспорт, оценочные полосы сети и доступные Wi-Fi RSSI/link rate. SSID/локация не собираются, точный LTE/5G стандарт может быть недоступен.
7. Game Session Tracker: foreground-события указанного пакета за последние 24 часа, по умолчанию com.riotgames.league.wildrift, только после добровольного предоставления Usage Access через настройки.
8. Charging Analyzer: напряжение/ток и температура именно батареи; сравнение с предыдущим ручным замером. Это НЕ мощность адаптера и не Bypass.
9. Session Comparison: фактические изменения заряда и температуры за два сохранённых сеанса в существующей SQLite v5.
10. System Health: RAM, свободное хранилище, PSS собственного процесса, режим дисплея.

Новые разрешения строго ограничены INTERNET, ACCESS_NETWORK_STATE, ACCESS_WIFI_STATE и PACKAGE_USAGE_STATS (спецдоступ включается пользователем). Нет Root, Shizuku, геолокации, QUERY_ALL_PACKAGES, фонового сервиса, доступа к чужим файлам, управления частотами или скрытого мониторинга. Сетевые подключения происходят только после нажатия. Все инструменты отключаются при выходе с экрана, внешняя отправка отчётов отсутствует.

Тесты: Kotlin/JVM вычислений и неполных значений, Python с реальным SQLite-запросом и строгим списком разрешений, существующие Android/Rust/релизные проверки. Необходим физический тест на Lenovo Y70 перед утверждением полной работоспособности.


## v0.1.0-alpha.15 — Hardware Lab (6 новых модулей)

По кнопке **HARDWARE LAB** внутри Gaming Lab открывается дополнительный экран с шестью настоящими функциями без Root/Shizuku:

1. **Local Route Inspector:** активный сетевой интерфейс Android, локальные IP, DNS и адреса шлюзов, состояние Private DNS через ConnectivityManager/LinkProperties. Данные могут принадлежать VPN, не обязательно Wi-Fi-роутеру; не сканируются соседи и не требуется геолокация.
2. **Network Events (30 с):** по нажатию регистрируется штатный NetworkCallback на 30 секунд; фиксируются события подключения, потери сети, валидации и изменений маршрута. До 64 событий, дубликаты ограничены. Это не ICMP ping, не сниффер трафика и не мониторинг игры.
3. **Storage Lab:** в приватном кэше создаётся временный файл 8 МиБ, измеряется последовательная запись с fsync и чтение, а данные проверяются SHA-256. Файл удаляется даже при ошибке. Чтение может ускоряться page cache Android — не официальный бенчмарк накопителя, результаты от условий зависят.
4. **Motion Stability (5 с):** реальные SensorEvent акселерометра и гироскопа, приближённый наклон от +Z, разброс ускорения и RMS угловой скорости. Отсутствующие/неверные значения не подменяются нулями. Не компас, не калибровка тача или акселерометра.
5. **Display Patterns:** ручной полноэкранный показ чёрного/белого/красного/зелёного/синего/серого. Нажатие переключает цвет, «Назад» закрывает проверку; системная яркость/частота дисплея не меняются. Дефектные пиксели оценивает сам пользователь, автоматической «диагностики пикселей» нет.
6. **Codec Inspector:** Android MediaCodecList показывает наличие доступных видеодекодеров AVC, HEVC, VP9, AV1 и отметку аппаратного ускорения. Наличие декодера не подтверждает возможность воспроизведения конкретного файла или производительность Wild Rift.

Доступна ручная отправка последнего текстового отчёта через системное меню. Все тесты явные и локальные; обработчики событий отменяются при сворачивании, запись/чтение Storage Lab работает на отдельном worker. **Не добавлены** дополнительные разрешения, новые таблицы SQLite или изменения Rust JNI. Все прежние функции alpha.14 сохранены, база остаётся SQLite v5; установка поверх предыдущей версии должна сохранять историю. Проверки GitHub Actions включают JVM-математику, контрактные тесты API/разрешений и прежнюю полную Android/Rust/пиннинг подписи цепочку. Физические датчики, сетевые callbacks и визуальную проверку дисплея нужно проверить на Lenovo Y70 отдельно.

 
## v0.1.0-alpha.16 — Compatibility Lab

Из Hardware Lab доступен новый экран Compatibility с семью ручными инструментами:

1. Display Modes & HDR: фактически объявленные Android режимы разрешения, частоты обновления, HDR и широкого цветового охвата; не измеряет FPS игры и не меняет частоту.
2. Audio Output Inspector: обнаруженные аудиовыходы, PCM-частоты и каналы, номинальный выходной буфер. Не измеряет задержку и не выбирает аудиомаршрут.
3. Gamepad Inventory: обнаруженные Android геймпады, vendor/product и число осей.
4. Gamepad Live: кнопки и аналоговые оси через KeyEvent/MotionEvent только внутри активного экрана. Нет глобального перехвата или управления чужими приложениями.
5. DRM / Widevine: наличие Widevine и доступные vendor/securityLevel, без открытия лицензии. Не подтверждает Netflix HD/4K.
6. Gaming Readiness: семь независимых факторов Android — температура и заряд батареи, Thermal Status, энергосбережение, герцы дисплея, сетевое подключение и нехватка RAM. Исходы OK, ВНИМАНИЕ, ОГРАНИЧЕНИЕ, НЕИЗВЕСТНО; неизвестные данные не подменяются нормой.
7. Quick Compute Probe: до 500 000 локальных целочисленных операций с контрольной суммой, отменой по выходу и блокировкой при зафиксированном сильном нагреве. Не измеряет частоты CPU/GPU и не является бенчмарком Wild Rift.

Полный текстовый отчёт по доступным возможностям создаётся в памяти только по нажатию и отправляется лишь по явному действию пользователя через системное меню. Нет нового Android разрешения, фона, серверных логов, SQLite-миграции или изменений Rust/JNI. Существующие battery.csv/ZIP и база v5 сохраняются. Реальные доступные свойства зависит от прошивки; аппаратную проверку выполняют на устройстве.

## v0.1.0-alpha.17 — универсальные Game Sessions (Android 13+)

Новый модуль **GAME SESSION** не привязан к Wild Rift или другому конкретному пакету. Пользователь выбирает видимое Android приложение в списке лаунчера (или вводит package name вручную), запускает запись, затем переключается в выбранную игру. На Android 13+ явно запущенная Foreground Service с уведомлением каждые ~15 секунд сохраняет доступные публичные показания Android: уровень и температуру батареи, ток при поддержке OEM, Thermal Status, энергосбережение, объявленную частоту дисплея и состояние активной сети. Служба останавливается по нажатию в приложении или уведомлении, не запускается при загрузке и не автоматически перезапускается системой. Прошивка может прервать запись; незавершённые сессии помечаются при следующем запуске.

Дополнительно сохраняются события сети и Thermal API, выводятся график температуры батареи, диагностические предупреждения, сравнение двух последних сессий, история и ручной экспорт game-samples.csv или полного ZIP с сессиями, замерами и событиями. **TCP-пробы на one.one.one.one:443 выполняются только при отдельном согласии пользователя**; Android network validation и TCP connect не являются игровым ping. Не измеряются FPS чужих приложений, CPU/GPU температура, Bypass/Touch Boost и не изменяются параметры ОС. Метка выбранного приложения сама по себе не доказывает, что оно было в foreground в течение всей записи.

Добавочная SQLite v5→v6 миграция создаёт только три новые таблицы, сохраняя старые данные и экспорты. Разрешения дополняются FOREGROUND_SERVICE, FOREGROUND_SERVICE_SPECIAL_USE и POST_NOTIFICATIONS (Android 13+; запрашивается отдельно); для списка ярлыков используется узкая `queries MAIN/LAUNCHER`, без QUERY_ALL_PACKAGES и без геолокации. Сертификат релизной подписи не меняется. Документ для тестирования и публикации на 4PDA: [docs/GAME-SESSIONS.md](docs/GAME-SESSIONS.md).
